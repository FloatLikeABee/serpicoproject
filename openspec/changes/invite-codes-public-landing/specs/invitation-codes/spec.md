## Purpose

Lets the backstage admin mint unique invitation codes with generated officer credentials, and lets invitees recover the same username and password from that code and sign into the officer app.

## ADDED Requirements

### Requirement: Admin can create an invitation

An authenticated admin SHALL be able to create an invitation without choosing a username or password. Creating an invitation SHALL produce one invitation code, one username, and one password, all generated by the system. The create response SHALL show the code, username, and password so the admin can copy them.

#### Scenario: Create invitation

- **WHEN** the admin requests a new invitation
- **THEN** the system returns a new unique code, a unique username, and a generated password

#### Scenario: Credentials are not typed by admin

- **WHEN** the admin creates an invitation
- **THEN** the username and password are assigned by the system, not entered as free text

### Requirement: Invitation codes are long, random, and unique

Each invitation code SHALL be at least 32 characters, generated from a cryptographic random source, and unique among all invitations. The system MUST reject creating a duplicate code.

#### Scenario: Code is long

- **WHEN** an invitation is created
- **THEN** its code is at least 32 characters

#### Scenario: Two creates are distinct

- **WHEN** the admin creates two invitations
- **THEN** their codes differ and their usernames differ

### Requirement: One invitation is one credential set

Each invitation SHALL map to exactly one username and one password. That pair SHALL be created when the invitation is created and SHALL not change afterward.

#### Scenario: Pair is fixed at create time

- **WHEN** an invitation is created
- **THEN** that invitation’s username and password are stored and remain the same on later views

### Requirement: Admin can list and copy invitations

The admin Users area SHALL list invitations with their codes, usernames, and passwords, and SHALL let the admin copy those values. Listing invitations SHALL require admin access and MUST NOT be available as a public API.

#### Scenario: Admin lists invitations

- **WHEN** the admin opens Users
- **THEN** existing invitations are shown with code, username, and password

#### Scenario: Public caller cannot list invitations

- **WHEN** an unauthenticated caller requests the invitation list
- **THEN** the system does not return invitation codes or passwords as a public list

### Requirement: Public redeem reveals the same credentials

A public page SHALL accept an invitation code. A valid code SHALL return that invitation’s username and password. Submitting the same valid code again SHALL return the same username and password.

#### Scenario: First redeem

- **WHEN** a visitor submits a valid unused or previously used invitation code
- **THEN** the page shows that invitation’s username and password

#### Scenario: Lost credentials

- **WHEN** a visitor submits the same valid code they used before
- **THEN** the page shows the same username and password as the first redeem

#### Scenario: Unknown code

- **WHEN** a visitor submits a code that is not an existing invitation
- **THEN** the system rejects the redeem and does not create an account

### Requirement: Redeem is rate limited

The redeem endpoint SHALL limit attempts per client so guessing long codes is not practical. After the limit is exceeded, further attempts SHALL fail until the window resets, including for a valid code.

#### Scenario: Too many attempts

- **WHEN** a client exceeds the redeem attempt limit in the window
- **THEN** further redeem requests from that client are rejected until the window resets

### Requirement: Invited users can sign into the officer app

The officer login SHALL accept an invited user’s username and password and SHALL establish a session as that user with role police. Invited users MUST NOT share the demo user id.

#### Scenario: Invited login succeeds

- **WHEN** a visitor signs in with an invitation’s username and password
- **THEN** they enter the officer app as that user with role police

#### Scenario: Wrong password fails

- **WHEN** a visitor signs in with an invited username and an incorrect password
- **THEN** login is rejected

### Requirement: Demo login still works

The existing demo username `serpico` and password `cops123` SHALL continue to sign in as the demo officer. Invitation usernames MUST NOT collide with `serpico`.

#### Scenario: Demo credentials

- **WHEN** a visitor signs in with `serpico` and `cops123`
- **THEN** they enter the officer app as the demo officer

#### Scenario: Invited username is not serpico

- **WHEN** an invitation is created
- **THEN** its username is not `serpico`
